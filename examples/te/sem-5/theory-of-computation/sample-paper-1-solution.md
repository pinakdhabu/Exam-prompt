## Q1) a) CYK Algorithm for String Membership [9]

**Given Grammar G (Chomsky Normal Form):**
```
S → AB | BC
A → BA | a
B → CC | b
C → AB | a
```
**String:** w = `aab`, length n = 3

**CYK Algorithm** builds a triangular table. Entry V[i][j] = set of variables that derive substring w[i...j].

**Step 1:** Fill diagonal (substrings of length 1):

| | j=1 | j=2 | j=3 |
|---|-----|-----|-----|
| i=1 | | | |
| i=2 | | | |
| i=3 | | | |

w[1]=a: V[1][1] = {A, C} (A→a, C→a)
w[2]=a: V[2][2] = {A, C}
w[3]=b: V[3][3] = {B}

**Step 2:** Length = 2 (substrings: w[1..2]=aa, w[2..3]=ab)

V[1][2]: split at k=1 → V[1][1] × V[2][2] = {A,C}×{A,C}
- A→BA: B∉V[1][1], A∉V[2][2]... wait
- S→AB: A∈V[1][1] and B∈... no B∉V[2][2]
- S→BC: B∉V[1][1]
- A→BA: B∉V[1][1]
- B→CC: C∈V[1][1] and C∈V[2][2] → B can be added
- C→AB: A∈V[1][1] and B∉V[2][2]

V[1][2] = {B}

V[2][3]: split at k=2 → V[2][2] × V[3][3] = {A,C}×{B}
- S→AB: A∈V[2][2] and B∈V[3][3] → S can be added
- S→BC: B∉V[2][2]
- A→BA: B∈V[2][2]... no B∉V[2][2]
- B→CC: C∈V[2][2]... C yes, but C∉V[3][3]
- C→AB: A∈V[2][2] and B∈V[3][3] → C can be added

V[2][3] = {S, C}

**Step 3:** Length = 3 (substring w[1..3] = aab)

V[1][3]:
- k=1: V[1][1] × V[2][3] = {A,C} × {S,C}
  - S→AB: A∈V[1][1] and B∉V[2][3]
  - S→BC: B∉V[1][1]
  - A→BA: B∉V[1][1]
  - B→CC: C∈V[1][1] and C∈V[2][3] → B can be added
  - C→AB: A∈V[1][1] and B∉V[2][3]

- k=2: V[1][2] × V[3][3] = {B} × {B}
  - S→AB: A∉V[1][2]
  - S→BC: B∈V[1][2] and C∉V[3][3]
  - B→CC: C∉V[1][2]
  - A→BA: B∈V[1][2] and A∉V[3][3]

V[1][3] = {B}

**Result:** S ∉ V[1][3]. The string `aab` is **NOT** a member of the language.

```
CYK Table:
        V[1][3]={B}
    V[1][2]={B}  V[2][3]={S,C}
V[1][1]={A,C} V[2][2]={A,C} V[3][3]={B}
         a          a          b
```

```
[ANSWER BOX]
String "aab" is NOT generated by the grammar (S ∉ V[1][3])
```

## Q2) b) CFG Design [8]

**i) L₁ = { aⁱ bʲ cᵏ | i = j + k, i, j, k ≥ 1 }**

Each 'a' generates either a 'b' or a 'c':
```
S → aSc | aTb      (a's matched with c's, then a's matched with b's)
T → aTb | ab       (remaining a's matched with b's)
```

For each `a`, we either produce a matching `c` (via S → aSc) or a matching `b` (via S → aTb, then T → aTb).

**Example:** a⁴ b² c²
```
S ⇒ aSc ⇒ a aSc c ⇒ a a aTb c c ⇒ a a a aTb b c c ⇒ a a a a b b c c
```

**ii) L₂ = { aⁱ bʲ cᵏ | j = i + k, i, j, k ≥ 1 }**

Each 'b' after i b's matches either an 'a' or a 'c':
```
S → bSc | aSb | bc     (center-out construction)
```

**Alternative (left-to-right):**
```
S → aSb | bSc | bc
```

**Example:** a² b⁵ c³ (j=5, i=2, k=3)
```
S ⇒ aSb ⇒ a aSb b ⇒ a a bSc b b ⇒ a a b bSc b b ⇒ a a b b bSc b b ⇒ a a b b b b c c c b b
```

Wait, let me reconsider the second language. For L₂ = {aⁱ bʲ cᵏ | j = i + k, i,j,k ≥ 1}:
- Total b's = a's + c's
- We can think: for every a, generate one b; for every c, generate one b

```
S → aSb | bSc | ε
```
But we need i,j,k ≥ 1. So:
```
S → aSb | bSc | abc   (base case: one a, one b, one c)
```

**Example:** a² b⁴ c²
```
S ⇒ aSb ⇒ a aSb b ⇒ a a abc b b = a² b³ c¹  -- not matching
```
Hmm, let me rethink. The constraint j=i+k means the b's in the middle equal the sum of a's (left) and c's (right). A better grammar:

```
S → aSb | T
T → bTc | bc
```

L₂: S generates i b's for i a's, then T generates k b's for k c's.

**Example:** a² b⁵ c³ (i=2, j=2+3=5, k=3)
```
S ⇒ aSb ⇒ a aSb b ⇒ a a T b b ⇒ a a bTc b b ⇒ a a b bTc b b ⇒ a a b b bTc b b ⇒ a a b b b bc b b
```

**Language:** L = { X c Xʳ | X ∈ {a, b}*, Xʳ = reverse of X }

**Idea:** Push X characters onto stack until 'c' is seen, then pop and match each input character against stack top.

**PDA Definition:** M = ({q₀, q₁, q₂}, {a, b, c}, {a, b, Z₀}, δ, q₀, Z₀, {q₂})

**Transitions:**
1. δ(q₀, ε, Z₀) = {(q₁, Z₀)}        — epsilon move to start
2. δ(q₁, a, Z₀) = {(q₁, aZ₀)}       — push a onto empty stack
3. δ(q₁, b, Z₀) = {(q₁, bZ₀)}       — push b onto empty stack
4. δ(q₁, a, a) = {(q₁, aa)}         — push a onto a
5. δ(q₁, a, b) = {(q₁, ab)}         — push a onto b
6. δ(q₁, b, a) = {(q₁, ba)}         — push b onto a
7. δ(q₁, b, b) = {(q₁, bb)}         — push b onto b
8. δ(q₁, c, Z₀) = {(q₁, Z₀)}        — c with no X (X=ε)
9. δ(q₁, c, a) = {(q₂, a)}          — c with a on stack → start popping
10. δ(q₁, c, b) = {(q₂, b)}         — c with b on stack
11. δ(q₂, a, a) = {(q₂, ε)}         — match a with top of stack
12. δ(q₂, b, b) = {(q₂, ε)}         — match b with top of stack
13. δ(q₂, ε, Z₀) = {(q₂, ε)}        — accept by final state with empty stack

**Processing `abcba`:**
```

                ⊢ (q₁, bcba, aZ₀)
                ⊢ (q₁, cba, baZ₀)

                ⊢ (q₂, a, aZ₀)          [b matches b on stack]
                ⊢ (q₂, ε, Z₀)           [a matches a on stack]
                ⊢ (q₂, ε, ε)            → ACCEPT
```

6. δ(q₂, a, A) = {(q₂, ε)}         — close a matches

Phase 4 — Accept:
7. δ(q₂, ε, Z₀) = {(q₃, ε)}        — accept with empty stack

## Q5) c) TM for 2's Complement [4]

**2's complement** = invert all bits after the first 1 from right (including that 1 itself).

**Procedure:** Scan right to first `1`, then scan left replacing: 0→1, 1→0 (after the first 1).

**Simpler approach:** Move to rightmost bit, then scan left:
- Keep all bits as-is until first 1 from right
- Then 0→1, 1→0

| State | Symbol | Next State | Write | Move |
|-------|--------|-----------|-------|------|
| q₀ | 0 | q₀ | 0 | R | Scan right |
| q₀ | 1 | q₁ | 1 | R | Found first 1 from left... |

Actually let me redesign. Better approach:

1. Scan to the rightmost end
2. Move left — keep bits unchanged until we see first 1
3. After seeing first 1 from right, flip all remaining bits (1→0, 0→1)

| State | Symbol | Next State | Write | Move |
|-------|--------|-----------|-------|------|
| q₀ | 0 | q₀ | 0 | R | Find right end |
| q₀ | 1 | q₀ | 1 | R |  |
| q₀ | B | q₁ | B | L | Reached right end |
| q₁ | 0 | q₁ | 0 | L | Skip trailing 0s |
| q₁ | 1 | q₂ | 1 | L | Found first 1 from right |
| q₁ | B | q₃ | B | R | All zeros → halt with 0 |
| q₂ | 0 | q₂ | 1 | L | Flip 0→1 |
| q₂ | 1 | q₂ | 0 | L | Flip 1→0 |
| q₂ | B | q₃ | B | R | Done |

**Example:** 2's complement of `0110` (6) = `1010` (-6 in 4-bit)
```
B 0 1 1 0 B → scan right to B → back L to 0 (unchanged)
→ back L to 1 (first 1 from right) → flip all from here: 1→0, 0→1
Wait: original 0110, first 1 from right at position 3 (0-indexed: 0 1 1 0)
Keep trailing 0s: 0110 → keep 0
First 1 from right at position 2: keep 1... no, the bit is 1, we keep it as is (not flipped)... 

Actually the standard algorithm for 2's complement:
1. Copy the number from right to left until you see the first 1
2. Copy that 1 as-is
3. Flip all remaining bits (0→1, 1→0)

So for 0110: bits from right = 0→copy, 1(second from right)→copy, 1→flip to 0, 0→flip to 1 → 1010 ✓
```

## Q7) b) Decidable, Undecidable Problems, Church-Turing Thesis [9]

**i) Decidable Problem:**
A problem is **decidable** if there exists an algorithm (Turing Machine) that always halts with a yes/no answer.

*Example:* Checking whether a string belongs to a regular language (DFA membership). Given DFA D and string w, we simulate D on w — it always halts.

**ii) Undecidable Problem:**
A problem is **undecidable** if no algorithm exists that always halts with a correct answer.

*Example:* The **Halting Problem** — given a TM M and input w, determine whether M halts on w. Turing proved this is undecidable via diagonalization. If a TM H could decide halting, we could construct a paradox machine that halts iff it doesn't halt.

**iii) Church-Turing Thesis:**
The **Church-Turing Thesis** states that any effectively computable function can be computed by a Turing Machine. It is a thesis (not a theorem) — a claim about the nature of computation.

*Implications:*
- All programming languages are equivalent in computational power (Turing-complete)
- If a problem cannot be solved by a TM, it cannot be solved by any computer
- Forms the foundation of computability theory

```
[ANSWER BOX]
Decidable → always halts (e.g., DFA membership)
Undecidable → no algorithm exists (e.g., Halting Problem)
Church-Turing → all effective computation = TM computation
```

## Q8) a) Reducibility and NP-Completeness [8]

**Reducibility:** Problem A is reducible to problem B (A ≤ B) if an algorithm for B can be used to solve A. If A is reducible to B and B is decidable, then A is decidable.

**Polynomial-time reduction (≤ₚ):** A ≤ₚ B if the reduction runs in polynomial time. Used to prove NP-completeness.

**NP-Complete Problem:** A problem is NP-complete if:
1. It is in NP (solution verifiable in polynomial time)
2. Every problem in NP reduces to it in polynomial time

**SAT → 3-SAT Reduction:**
- SAT: Boolean formula with arbitrary clauses
- 3-SAT: Each clause must have exactly 3 literals

*Reduction example:* Convert clause (x ∨ y) to:
- (x ∨ y ∨ z) ∧ (x ∨ y ∨ ¬z) — both must be true, so x ∨ y is equivalent

Each clause with k literals can be converted to a conjunction of 3-literal clauses using auxiliary variables.

**Cook-Levin Theorem:** SAT is NP-complete — the first problem proven NP-complete.

```
[ANSWER BOX]
SAT is NP-Complete (Cook-Levin Theorem, 1971)
3-SAT is also NP-Complete (via ≤ₚ reduction from SAT)
```

## Q8) b) Halting Problem, Multi-tape TM, Universal TM [9]

**i) Halting Problem of TM:**
Given TM M and input w, does M halt when run on w?

*Undecidability proof (by contradiction):*
- Assume H exists: H(M, w) = "halts" if M halts on w, "loops" otherwise
- Construct H': run H(M, M); if "halts" then loop forever, if "loops" then halt
- Run H' on itself: H'(H') halts ⇔ H'(H') loops → contradiction
- Therefore H cannot exist.

**ii) Multi-tape TM:**
A TM with k independent tapes, each with its own read/write head.

```mermaid

    subgraph Control Unit
        F[Finite Control]
    end
    subgraph Tape 1
        T1[...|0|1|1|B|...]
    end
    subgraph Tape 2

    end
    subgraph Tape 3
        T3[...|B|...]
    end

    F --> T2
    F --> T3
```

*Power:* Multi-tape TMs are equivalent to single-tape TMs (any multi-tape TM can be simulated by a single-tape TM with O(n²) overhead).

**iii) Universal TM (UTM):**
A UTM is a TM that can simulate any other TM given its description.

- **Input:** ⟨M, w⟩ — encoded description of TM M and its input w
- **Operation:** UTM reads the transition rules of M from its own tape, then simulates M step by step on w
- **Significance:** Forms the theoretical basis for stored-program computers

```
[ANSWER BOX]
Halting Problem: Undecidable (proven by diagonalization)
Multi-tape TM: Equivalent to single-tape TM
Universal TM: Can simulate any TM — foundation of general-purpose computing
```
