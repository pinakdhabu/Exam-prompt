### Unit III — Object-Oriented Modeling

**Q1)** **a)** Explain the concept of Object-Oriented Modeling (OOM). Describe the three models of
OMT: Object Model, Dynamic Model, and Functional Model. How do they relate to each other? [9]

**b)** Draw a UML Class Diagram for a Library Management System. Include classes: Library, Member,
Book, Librarian, and Transaction. Show relationships (association, aggregation, inheritance) with
multiplicities. [9]

**OR**

**Q2)** **a)** Explain the Unified Modeling Language (UML) in detail. Describe the types of UML
diagrams: structural (class, component, deployment) and behavioral (use case, sequence, activity,
state machine). [9]

**b)** Draw a UML Sequence Diagram for the "Borrow Book" use case in a library system. Show
interactions between Member, Librarian, Book, and Database objects. Include alternate and exception
flows. [9]

---

### Unit IV — Design Patterns

**Q3)** **a)** What are design patterns? Explain the GoF (Gang of Four) classification of patterns
into Creational, Structural, and Behavioral categories with two examples each. [9]

**b)** Implement the Singleton design pattern in Java. Explain when Singleton should be used.
Discuss the issues with Singleton: thread safety, serialization, and testing. [8]

**OR**

**Q4)** **a)** Explain the Observer design pattern. Provide a real-world example with a class
diagram and Java/C++ pseudocode. Discuss the push vs pull models of notification. [9]

**b)** Compare the Strategy and State design patterns. How are they similar? When would you choose
one over the other? Provide implementation sketches for both. [8]

---

### Unit V — Component-Based and Service-Oriented Architecture

**Q5)** **a)** Explain Component-Based Software Engineering (CBSE). Describe the principles of
component design: reusability, replaceability, independence, and encapsulation. Compare components
with objects. [9]

**b)** What is Service-Oriented Architecture (SOA)? Explain the SOA principles: loose coupling,
service abstraction, reusability, autonomy, statelessness, discoverability, and composability. [9]

**OR**

**Q6)** **a)** Compare SOA (Service-Oriented Architecture) with Microservices architecture. Discuss
the differences in service granularity, communication, data management, and deployment. [9]

**b)** Explain RESTful Web Services. Describe REST principles (stateless, uniform interface,
cacheable, layered system) with HTTP methods (GET, POST, PUT, DELETE) and resource naming
conventions. [9]

---

### Unit VI — Architecture Evaluation and Documentation

**Q7)** **a)** Explain the ATAM (Architecture Tradeoff Analysis Method) process. Describe the steps:
presentation, business driver analysis, architecture presentation, scenario brainstorming, analysis,
and results. [9]

**b)** What is the 4+1 View Model of software architecture? Explain each view: Logical, Process,
Development, Physical, and Scenarios (+1). How do these views address different stakeholder
concerns? [8]

**OR**

**Q8)** **a)** Explain IEEE 1471-2000 (Recommended Practice for Architectural Description of
Software-Intensive Systems). Describe the conceptual framework: mission, environment, system,
architecture, architectural description, stakeholder, concern, view, viewpoint, and rationale. [9]

**b)** Write short notes on any two: i) Software Architecture Documentation ii) Architecture
Decision Records (ADRs) iii) SAAM (Software Architecture Analysis Method) [8]

## Examiner Commentary

This paper covers the complete SMA syllabus: OO modeling (OMT, UML diagrams), design patterns (GoF,
Singleton, Observer, Strategy, State), component-based and service-oriented architecture (CBSE, SOA,
Microservices, REST), and architecture evaluation (ATAM, 4+1 View Model, IEEE 1471). The UML diagram
questions test practical modeling skills, while the pattern implementation questions assess design
competency.
